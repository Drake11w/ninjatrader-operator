# ninjatrader-operator

MCP server that lets an agent monitor NinjaTrader 8 (accounts, P&L, positions) and apply risk-reducing controls. Experimental strategy start/stop is also available behind separate Sim and live-small gates; it is not a general-purpose order-entry API.

- `NtStatusAddOn.cs` - NinjaScript add-on. Copy to `Documents\NinjaTrader 8\bin\Custom\AddOns\`, open the NinjaScript Editor and press F5. Serves JSON (localhost only; GET for data, POST only for the controls below) at `/status`, `/orders`, `/executions?limit=N`, `/strategies` and `/health`, plus (experimental, see Backtests below) `POST /backtest/run`, `GET /backtest/job` and the read-only `GET /debug/types?filter=...&members=1` that lists NinjaTrader's own types for reverse engineering.
- `server.py` - Python MCP server (`pip install mcp`, tested with mcp 2.x) exposing `get_accounts`, `get_positions`, `get_orders`, `get_executions`, `get_strategies` and `get_health`, plus `sync_journal` / `get_journal` (local SQLite trade journal at `~/.ninjatrader-operator/journal.sqlite`, override with `NT_JOURNAL_DB`; `journal.py` holds the logic), `validate_strategy_spec` (shared strategy spec draft, see `STRATEGY_SPEC.md`), `submit_strategy` / `set_strategy_status` / `list_submitted_strategies` / `get_submitted_strategy` `import_backtest` / `list_backtests` / `check_backtest` / `compare_backtest_to_journal` (Strategy Analyzer CSV ingestion and drift check; `backtest.py`), (spec registry with candidate -> backtest -> sim -> live-small -> live lifecycle at `~/.ninjatrader-operator/registry.sqlite`, override with `NT_REGISTRY_DB`; `registry.py`; bookkeeping only), `get_session_info` (RTH/Globex state, time to open/close, front-month roll; `sessions.py`), `get_report` (daily/weekly markdown report; `report.py`), `get_rule_status` (prop-firm distance-to-breach; needs a rules file, see `rules.example.json`, placeholder values), and `get_trades` / `get_performance` (round-trip trades and metrics from the journal; `trades.py`; P&L uses a built-in point-value table, override with `point_values`). Every reply carries `age_seconds` and a `warning` if the data is stale. Set `NT_ADDON_URL` to point at a different add-on address. Tests: `python -m unittest discover tests` (fake add-on, no NinjaTrader needed).

Register in Claude Desktop's MCP config:

```json
{"mcpServers":{"ninjatrader":{"command":"python","args":["C:/path/to/server.py"]}}}
```

Controls (`flatten`, `cancel_all_orders`, `arm_kill_switch`, `disarm_kill_switch`, `get_kill_switch`, `get_audit_log`; `control.py`): Accounts named `Sim*` only, plus any exact names in `NT_OPERATOR_ALLOWED_ACCOUNTS` (comma-separated, set in both the NT8 and MCP environments, e.g. your Lucid sim account), or everything with `NT_OPERATOR_ALLOW_LIVE=1` (add-on and server both enforce it); account must be named explicitly; set `NT_OPERATOR_TOKEN` (same value in the NT8 and MCP environments) to require an `X-NT-Token` header; every attempt, including refusals, goes to `~/.ninjatrader-operator/audit.jsonl` (`NT_AUDIT_FILE`).

Experimental strategy deployment (`enable_strategy`, `deploy_strategy_live_small`, `disable_strategy`): `enable_strategy` is Sim-only and defaults to `skip_defaults=1` because `StrategiesGrid.StrategySetDefaults` throws a `NullReferenceException` in the verified NT 8.1.8.4 setup. Live-small deployment is a distinct action and requires the registered version to be exactly `live-small`, plus `NT_OPERATOR_ALLOW_LIVE_SMALL=1`, `NT_OPERATOR_ALLOW_STRATEGY_START=1`, and the exact account in `NT_OPERATOR_LIVE_SMALL_ACCOUNTS` (comma-separated). Set the live-small variables in **both** the Python server and NinjaTrader process environments; the add-on independently checks them. The broad `NT_OPERATOR_ALLOW_LIVE=1` and `NT_OPERATOR_ALLOWED_ACCOUNTS` settings do not authorize strategy starts on real accounts. Every attempt is audited. This reflection-based start path is experimental and has only been verified on NT 8.1.8.4 / Sim101; live-small has not been verified on a real account. Strategy `max_contracts` is not a broker-side loss limit; configure independent broker/prop risk controls before any real deployment. The kill switch runs inside the add-on (works with Claude closed): once P&L since arming reaches -max_loss it flattens and cancels every 2s until disarmed. It only flattens, it does not disable strategies, and it lives in memory (restarting NT8 disarms it). Cancelling all orders also cancels protective stops.

Note: the control endpoints and the new add-on endpoints (orders, executions, strategies, health) have not been compiled in NT8 yet; `Account.Strategies` in particular needs confirming. Planned: regime status; pause/resume only with a daily-loss cap and kill switch enforced server-side; order entry last, if ever.

Dashboard: `python dashboard.py` serves a read-only page at http://127.0.0.1:8766 (`NT_DASHBOARD_PORT` to change; `dashboard.py` + `dashboard.html`). One card per registered strategy: stage, handoff approval (recorded by `install_handoff` with apply=true; older installs show "not recorded" until re-applied), time running since it entered sim, live NinjaTrader state per leg, net P&L / today / win rate / expectancy / drawdown since activation, equity curve, sim vs backtest comparison, verdict with every check, stage and verdict history. Refreshes every 15s and syncs new fills into the journal. It never sends control commands.

Backtests (`backtest_runner.py`, add-on `/backtest/*`; experimental, NT 8.1.8.4 only): `python backtest_runner.py <bundle dir> [--start --end --out runs --stitch --import]` runs every leg of a handoff bundle in NinjaTrader's Strategy Analyzer through the add-on, applies the commission afterwards ($0.62 per side from the spec; slippage is applied by NinjaTrader), writes a Trades-grid CSV and, with `--import`, stores it in the registry and checks it against `expected_metrics`. Rules learned the hard way: (1) keep ONE Strategy Analyzer window open and idle, because the add-on drives it and every recompile of the add-on closes it; (2) the instrument is the current front-month contract (e.g. `MNQ 12-26`), over the whole range: NinjaTrader merges the earlier contracts into it, so history reaches back to 2019. The continuous `MNQ ##-##` gave empty results, so it is not used. `--stitch` runs one contract per window as a fallback, but prior-day filters then lose their warm-up at the start of each window; (3) creating an Analyzer window from code crashes the Analyzer's Run command until NinjaTrader is restarted; (4) Windows Application Control occasionally blocks the freshly compiled add-on DLL (error 0x800711C7): press F5 again. First verified run: S742 (both legs, 2020-01-02 to 2026-10-16) gave 858 trades, profit factor 1.519, net $5,672 per year, max drawdown $2,761, all within 15% of the spec. `BACKTEST_RUNSHEET.md` lists the settings for doing the same runs by hand.
