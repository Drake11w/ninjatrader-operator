# ninjatrader-operator

MCP server that lets an agent monitor NinjaTrader 8 (accounts, P&L, positions) and apply risk-reducing controls. Experimental strategy start/stop is also available behind separate Sim and live-small gates; it is not a general-purpose order-entry API.

- `NtStatusAddOn.cs` - NinjaScript add-on. Copy to `Documents\NinjaTrader 8\bin\Custom\AddOns\`, open the NinjaScript Editor and press F5. Serves JSON (localhost only; GET for data, POST only for the controls below) at `/status`, `/orders`, `/executions?limit=N`, `/strategies` and `/health`, plus (experimental, see Backtests below) `POST /backtest/run`, `GET /backtest/job` and the read-only `GET /debug/types?filter=...&members=1` that lists NinjaTrader's own types for reverse engineering.
- `server.py` - Python MCP server (`pip install mcp`, tested with mcp 2.x) exposing `get_accounts`, `get_positions`, `get_orders`, `get_executions`, `get_strategies` and `get_health`, plus `sync_journal` / `get_journal` (local SQLite trade journal at `~/.ninjatrader-operator/journal.sqlite`, override with `NT_JOURNAL_DB`; `journal.py` holds the logic), `validate_strategy_spec` (shared strategy spec draft, see `STRATEGY_SPEC.md`), `submit_strategy` / `set_strategy_status` / `list_submitted_strategies` / `get_submitted_strategy` `import_backtest` / `list_backtests` / `check_backtest` / `compare_backtest_to_journal` (Strategy Analyzer CSV ingestion and drift check; `backtest.py`), (spec registry with candidate -> backtest -> sim -> live-small -> live lifecycle at `~/.ninjatrader-operator/registry.sqlite`, override with `NT_REGISTRY_DB`; `registry.py`; bookkeeping only), `get_session_info` (RTH/Globex state, time to open/close, front-month roll; `sessions.py`), `get_report` (daily/weekly markdown report; `report.py`), `get_rule_status` (prop-firm distance-to-breach; needs a rules file, see `rules.example.json`, placeholder values), and `compare_backtest_to_sim` (backtest vs sim on identical metrics with flags; `comparison.py`), and `get_trades` / `get_performance` (round-trip trades and metrics from the journal; `trades.py`; P&L uses a built-in point-value table, override with `point_values`). Every reply carries `age_seconds` and a `warning` if the data is stale. Set `NT_ADDON_URL` to point at a different add-on address. Tests: `python -m unittest discover tests` (fake add-on, no NinjaTrader needed).

Register in Claude Desktop's MCP config:

```json
{"mcpServers":{"ninjatrader":{"command":"python","args":["C:/path/to/server.py"]}}}
```

Controls (`flatten`, `cancel_all_orders`, `arm_kill_switch`, `disarm_kill_switch`, `get_kill_switch`, `get_audit_log`; `control.py`): Accounts named `Sim*` only, plus any exact names in `NT_OPERATOR_ALLOWED_ACCOUNTS` (comma-separated, set in both the NT8 and MCP environments, e.g. your Lucid sim account), or everything with `NT_OPERATOR_ALLOW_LIVE=1` (add-on and server both enforce it); account must be named explicitly; set `NT_OPERATOR_TOKEN` (same value in the NT8 and MCP environments) to require an `X-NT-Token` header; every attempt, including refusals, goes to `~/.ninjatrader-operator/audit.jsonl` (`NT_AUDIT_FILE`).

Reconnect recovery watchdog (NtStatusAddOn): polls NinjaTrader every 5 seconds, remembers strategies that were `Realtime` while their account and price feed were healthy, and can request re-enable after both are restored continuously for at least 30 seconds. It is **off by default** and only applies to existing strategy instances; it does not create new instances. To opt in, set all of: `NT_OPERATOR_AUTO_RECOVER=1`, `NT_OPERATOR_ALLOW_STRATEGY_START=1`, exact comma-separated `NT_OPERATOR_AUTO_RECOVER_ACCOUNTS`, and exact comma-separated `NT_OPERATOR_AUTO_RECOVER_STRATEGIES` in the NinjaTrader process environment, then restart NinjaTrader. For real accounts, the existing live-small gates must also pass (`NT_OPERATOR_ALLOW_LIVE_SMALL=1`, exact `NT_OPERATOR_LIVE_SMALL_ACCOUNTS`, and `NT_OPERATOR_TOKEN`). Recovery waits for a stable connection/feed, requires the strategy still to exist, and refuses to restart if that instrument has any open position or working order. Check status with `get_recovery_status` or `GET /recovery`. This is intentionally conservative: a blocked strategy is left stopped for manual review. Recovery memory is in-process only; it does not survive an NT/add-on restart, and it cannot infer user intent if a strategy is manually stopped during the outage. It is experimental and must first be validated on Sim101; it has not been compiled or verified in NinjaTrader yet.

Experimental strategy deployment (`enable_strategy`, `deploy_strategy_live_small`, `disable_strategy`): `enable_strategy` is Sim-only and defaults to `skip_defaults=1` because `StrategiesGrid.StrategySetDefaults` throws a `NullReferenceException` in the verified NT 8.1.8.4 setup. Live-small deployment is a distinct action and requires the registered version to be exactly `live-small`, plus `NT_OPERATOR_ALLOW_LIVE_SMALL=1`, `NT_OPERATOR_ALLOW_STRATEGY_START=1`, and the exact account in `NT_OPERATOR_LIVE_SMALL_ACCOUNTS` (comma-separated). Set the live-small variables in **both** the Python server and NinjaTrader process environments; the add-on independently checks them. The broad `NT_OPERATOR_ALLOW_LIVE=1` and `NT_OPERATOR_ALLOWED_ACCOUNTS` settings do not authorize strategy starts on real accounts. Every attempt is audited. This reflection-based start path is experimental and has only been verified on NT 8.1.8.4 / Sim101; live-small has not been verified on a real account. Stale Strategies-tab entries: NinjaTrader drops stopped instances from `Account.Strategies`, so `get_strategies` cannot see them. `list_strategy_rows` (add-on `GET /strategy/rows`, from `StrategyBase.All`) lists everything NinjaTrader still holds, and `purge_strategy_rows` (add-on `POST /strategy/purge`, dry run unless `confirm`) removes only Finalized/Terminated flat strategies, plus a `Configure` duplicate of a running strategy when named with `name`. Never touches Realtime or other Configure rows; same guards and audit as `disable_strategy`. Verified on NT 8.1.8.4. Strategy `max_contracts` is not a broker-side loss limit; configure independent broker/prop risk controls before any real deployment. The kill switch runs inside the add-on (works with Claude closed): once P&L since arming reaches -max_loss it flattens and cancels every 2s until disarmed. It only flattens, it does not disable strategies, and it lives in memory (restarting NT8 disarms it). Cancelling all orders also cancels protective stops.

Note: the control endpoints and the new add-on endpoints (orders, executions, strategies, health) have not been compiled in NT8 yet; `Account.Strategies` in particular needs confirming. Planned: regime status; pause/resume only with a daily-loss cap and kill switch enforced server-side; order entry last, if ever.

Dashboard: `python dashboard.py` serves a read-only page at http://127.0.0.1:8766 (`NT_DASHBOARD_PORT` to change; `dashboard.py` + `dashboard.html`). One card per registered strategy: stage, handoff approval (recorded by `install_handoff` with apply=true; older installs show "not recorded" until re-applied), time running since it entered sim, live NinjaTrader state per leg, net P&L / today / win rate / expectancy / drawdown since activation, equity curve, sim vs backtest comparison, verdict with every check, stage and verdict history. Refreshes every 15s and syncs new fills into the journal. It also has a read-only Supervisor panel (daemon heartbeat, active incidents, performance-check status, incident history) and a per-strategy "Backtest vs sim" table. It never sends control commands.

Backtests (`backtest_runner.py`, add-on `/backtest/*`; experimental, NT 8.1.8.4 only): `python backtest_runner.py <bundle dir> [--start --end --out runs --stitch --import]` runs every leg of a handoff bundle in NinjaTrader's Strategy Analyzer through the add-on, applies the commission afterwards ($0.62 per side from the spec; slippage is applied by NinjaTrader), writes a Trades-grid CSV and, with `--import`, stores it in the registry and checks it against `expected_metrics`. Rules learned the hard way: (1) keep ONE Strategy Analyzer window open and idle, because the add-on drives it and every recompile of the add-on closes it; (2) the instrument is the current front-month contract (e.g. `MNQ 12-26`), over the whole range: NinjaTrader merges the earlier contracts into it, so history reaches back to 2019. The continuous `MNQ ##-##` gave empty results, so it is not used. `--stitch` runs one contract per window as a fallback, but prior-day filters then lose their warm-up at the start of each window; (3) creating an Analyzer window from code crashes the Analyzer's Run command until NinjaTrader is restarted; (4) Windows Application Control occasionally blocks the freshly compiled add-on DLL (error 0x800711C7): press F5 again. First verified run: S742 (both legs, 2020-01-02 to 2026-10-16) gave 858 trades, profit factor 1.519, net $5,672 per year, max drawdown $2,761, all within 15% of the spec. `BACKTEST_RUNSHEET.md` lists the settings for doing the same runs by hand.

Historical data (`history.py`, MCP tool `download_history`, add-on `GET /history`; read-only, experimental): `python history.py "MNQ 12-26" --start 2024-01-01 [--end ...] [--type Minute --value 1]` pulls bars through NinjaTrader's BarsRequest (the same data the Strategy Analyzer uses; the front-month contract merges earlier ones) and merges them into `~/Desktop/Market Data/<instrument>_<type><value>.csv` (`NT_HISTORY_DIR`), columns time,open,high,low,close,volume, times in NinjaTrader local time (bar close). Requests are chunked by date, so re-running just updates the file. The add-on endpoint has not been compiled in NT8 yet: press F5 in the NinjaScript Editor, then try a short range first. Tick options (Nov 12; also uncompiled): `price=Last|Bid|Ask`, `merge=backadjusted|nonbackadjusted|none`, `offset` / `limit` paging and `fmt=tick` (rows `[time, price, volume]`, 7-digit seconds). The reply echoes `price`, `merge`, `total`, `offset`, `fmt`, so a client can tell an add-on that has not been recompiled (it ignores the options and would silently return Last data). NinjaTrader returns the whole trading session for a Tick request (from 17:00 the evening before), millions of ticks a day, hence the paging; the lucid-trading-system nightly job (`datapipe/nt_ticks.py`) uses it.

Feedback export (`feedback.py`, `readiness.py`, MCP tool `export_feedback`; read-only): writes an immutable snapshot of a registered strategy version's results (trades, daily P&L, summary, verdict with a live-small readiness block, drift flags, backtest check) to `NT_FEEDBACK_DIR` (default `~/.ninjatrader-operator/feedback/`, never committed) as `<lucid_id>/<version>/<as_of>/` plus `latest.json`, for the Lucid research side to read. Account names are exported as aliases. Schema: `docs/feedback/SCHEMA.md`, `feedback.schema.json`; synthetic examples in `examples/feedback/`. It changes no status and has no path to NinjaTrader (`tests/test_no_new_post_path.py`).

Nudge list (`nudges.py`, MCP tool `list_nudges`, plus a "Ready for live-small" dashboard panel; read-only, needs no secret): lists Sim versions that meet every readiness criterion right now, using the same `readiness` module as the export. Computed fresh each call and never stored, so a nudge disappears when readiness lapses. It changes no status and has no path to NinjaTrader.

Promotion (`promote.py`, MCP tool `promote_strategy`): one explicit command takes a Lucid handoff bundle through install (candidate), a Strategy Analyzer backtest and import (backtest), a check against the spec's `expected_metrics`, and a Sim start (sim). It stops at the first failed stage with no override, resumes by skipping completed stages, holds a single-flight lock and writes `promotion_report.json` next to the feedback snapshots. Ceiling is Sim: it never touches `live-small` or `live`, and the Sim start still needs `NT_OPERATOR_ALLOW_STRATEGY_START=1`.

Approval (`approvals.py`, MCP tools `approve_live_small`, `schedule_live_small_approval`, `cancel_scheduled_approval`, `list_scheduled_approvals`): the only code that moves a version to `live-small`, and it changes registry status only; it starts nothing and never satisfies an `NT_OPERATOR_*` gate. Owner-only: the caller passes the approval secret per call, and the server environment holds only its SHA-256 (`NT_OPERATOR_APPROVAL_SECRET_SHA256`) plus `NT_OPERATOR_TOKEN`. A scheduled approval is executed (or voided if readiness lapsed, the version left `sim`, or it expired; default expiry 24 h) by a registry-only step in the launcher tick, so timing has 30-minute granularity inside the enable window. Tables `live_small_approvals` and `scheduled_approvals`; every event also goes to `audit.jsonl`. Rollout and verification: `docs/LUCID_LOOP_ROLLOUT.md`; daily export task: `scripts/install_export_task.ps1`.

Strategy Supervisor (Phase 1, observe/record/notify only; `sup_*.py`, design in `docs/supervisor/`): `python sup_daemon.py` polls the add-on's `/health` and `/strategies` (GET only) every 10 s, checks them against profiles (`supervisor_profiles.example.json`, copy to `~/.ninjatrader-operator/supervisor_profiles.json` or set `NT_SUPERVISOR_PROFILES`), keeps incidents in `~/.ninjatrader-operator/supervisor.sqlite` (`NT_SUPERVISOR_DB`), and writes an alert log, an attention-flag file and an opt-in Windows toast (`NT_SUPERVISOR_TOAST=1`, untested). `--once` runs one cycle; `--status` prints heartbeat age and exits 1 if stale. Every 5 minutes it also compares each active registered strategy with its backtest (`sup_perf.py`, `sup_behavior.py`: verdict-engine drift, trade pace, holding time; warning level only, nothing is disabled). It never sends control commands. `sup_watch.py --notify` (scheduled every 2 minutes by `scripts/install_watch_task.ps1`) reports a dead daemon or new severity 2+ incidents once each as a Windows toast, and POSTs to `NT_WATCH_PUSH_URL` if you set it (opt-in; for example an ntfy.sh topic, which sends the alert text to that service). A profile may carry `"active_ct": {"days": [0,1,2,3,4], "from": "08:15", "until": "15:00"}` (Central time): outside it the instance is not expected to exist, so it is never reported missing, not running or stopped; without it the instance is expected around the clock. From Friday 16:00 CT to Sunday 16:45 CT a closed or disconnected NinjaTrader is not reported either (`sessions.weekend_closed`). On an exchange holiday, halt day or early close a profile with an `active_ct` window is not expected at all that day (the launcher does not enable it). Wrong-account checks run at all times. When the add-on does not answer, the incident says why, from the Windows process list and window titles (`nt_local.py`, never NinjaTrader itself): not running, at the login window, or running with the add-on silent. The watcher also reports the launcher when it is enabled but has never run, has not run for 75 minutes, or its last run failed (it writes `launcher_heartbeat.json` on every `--apply`). Failure testing: `docs/supervisor/GATE1_CHECKLIST.md`. Not yet run against a real NinjaTrader: the add-on endpoints it reads still need the Gate 0 check (`docs/supervisor/GATE0_CHECKLIST.md`).


Launcher (`launcher.py`, `scripts/install_launcher_task.ps1`; separate from the read-only supervisor): starts NinjaTrader (minimized, not activated, so it does not pull a game out of fullscreen) and enables the strategy that is currently live (registry status `live-small`; `live` is never auto-started on a real account) when it is meant to run. With `"enable_sim": true` (the default) it also enables `sim`-stage strategies, but only on a Sim* account (e.g. Sim101); a `sim` strategy whose profile names a real account is refused. The account comes from the strategy's supervisor profile. It is idempotent, runs as a scheduled task every 30 minutes, and does nothing until `"enabled": true` is set in `~/.ninjatrader-operator/launcher.json` (see `launcher.example.json`). It starts NinjaTrader whenever the exchange is open (quiet from Friday 16:00 CT to Sunday 16:45 CT) and enables strategies only inside the enable window (default Mon-Fri 07:30-15:00 CT), only if the add-on is up and the account's connection and data feed are Connected, the account is flat with nothing else running, all `NT_OPERATOR_*` live-small gates pass, and the strategy has not already been enabled today (stop one by hand and it stays stopped until tomorrow; `--resume-today` overrides). Partial presence is left alone. `python launcher.py` is a dry run; `--apply` acts; `--pause` / `--resume` stop and restart it; `--status` shows state. Every action is audited. It cannot log in for you, and NinjaTrader 8.1 asks for the password on every launch (BUG-001), so a restart stops at the login window until someone logs in. The launcher alerts when it sees that window (unless the supervisor is running, which reports it instead). The kill switch is Sim-only, so a real account has no add-on loss limit here; use the broker/prop-firm limits. Holidays: with `"skip_holidays": true` (the default) nothing is enabled on an exchange holiday, a midday-halt day or an early-close day (for example Thanksgiving and the Friday after), because a leg could not hold to its usual exit; NinjaTrader is still started and scheduled approvals still run. The list comes from date rules in `sessions.py` (`special_sessions`), not from the exchange, so add one-off closures to `"extra_holidays": ["YYYY-MM-DD"]` and check the CME calendar; set `skip_holidays` to false to enable every weekday as before.

Known issues: see `docs/KNOWN_ISSUES.md` (BUG-001: the launcher cannot recover NinjaTrader unattended because NinjaTrader returns to its login window after a crash).
