# ninjatrader-operator

MCP server that lets Claude monitor NinjaTrader 8 (accounts, P&L, positions) and apply risk-reducing controls: flatten, cancel all orders, daily-loss kill switch. No order entry.

- `NtStatusAddOn.cs` - NinjaScript add-on. Copy to `Documents\NinjaTrader 8\bin\Custom\AddOns\`, open the NinjaScript Editor and press F5. Serves JSON (localhost only; GET for data, POST only for the controls below) at `/status`, `/orders`, `/executions?limit=N`, `/strategies` and `/health`.
- `server.py` - Python MCP server (`pip install mcp`, tested with mcp 2.x) exposing `get_accounts`, `get_positions`, `get_orders`, `get_executions`, `get_strategies` and `get_health`, plus `sync_journal` / `get_journal` (local SQLite trade journal at `~/.ninjatrader-operator/journal.sqlite`, override with `NT_JOURNAL_DB`; `journal.py` holds the logic), `validate_strategy_spec` (shared strategy spec draft, see `STRATEGY_SPEC.md`), `submit_strategy` / `set_strategy_status` / `list_submitted_strategies` / `get_submitted_strategy` `import_backtest` / `list_backtests` / `check_backtest` / `compare_backtest_to_journal` (Strategy Analyzer CSV ingestion and drift check; `backtest.py`), (spec registry with candidate -> backtest -> sim -> live-small -> live lifecycle at `~/.ninjatrader-operator/registry.sqlite`, override with `NT_REGISTRY_DB`; `registry.py`; bookkeeping only), `get_session_info` (RTH/Globex state, time to open/close, front-month roll; `sessions.py`), `get_report` (daily/weekly markdown report; `report.py`), `get_rule_status` (prop-firm distance-to-breach; needs a rules file, see `rules.example.json`, placeholder values), and `get_trades` / `get_performance` (round-trip trades and metrics from the journal; `trades.py`; P&L uses a built-in point-value table, override with `point_values`). Every reply carries `age_seconds` and a `warning` if the data is stale. Set `NT_ADDON_URL` to point at a different add-on address. Tests: `python -m unittest discover tests` (fake add-on, no NinjaTrader needed).

Register in Claude Desktop's MCP config:

```json
{"mcpServers":{"ninjatrader":{"command":"python","args":["C:/path/to/server.py"]}}}
```

Controls (`flatten`, `cancel_all_orders`, `arm_kill_switch`, `disarm_kill_switch`, `get_kill_switch`, `get_audit_log`; `control.py`): Accounts named `Sim*` only, plus any exact names in `NT_OPERATOR_ALLOWED_ACCOUNTS` (comma-separated, set in both the NT8 and MCP environments, e.g. your Lucid sim account), or everything with `NT_OPERATOR_ALLOW_LIVE=1` (add-on and server both enforce it); account must be named explicitly; set `NT_OPERATOR_TOKEN` (same value in the NT8 and MCP environments) to require an `X-NT-Token` header; every attempt, including refusals, goes to `~/.ninjatrader-operator/audit.jsonl` (`NT_AUDIT_FILE`). The kill switch runs inside the add-on (works with Claude closed): once P&L since arming reaches -max_loss it flattens and cancels every 2s until disarmed. It only flattens, it does not disable strategies, and it lives in memory (restarting NT8 disarms it). Cancelling all orders also cancels protective stops.

Note: the control endpoints and the new add-on endpoints (orders, executions, strategies, health) have not been compiled in NT8 yet; `Account.Strategies` in particular needs confirming.
